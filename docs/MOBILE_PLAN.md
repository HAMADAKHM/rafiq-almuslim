# خطة الانتقال إلى Android ثم iPhone

> **تحديث 0.2:** نُفذت المرحلتان الثانية والثالثة برمجيًا (مشروعا `android/` و`ios/`، الإشعارات المحلية المجدولة، الموقع، المشاركة، الاهتزاز، الصوت في الخلفية على iOS). لم يُبنَ التطبيق بعد بسبب قيود بيئة البناء — انظر [تقرير 0.2](REPORT_v0.2.md).
> رسالة الوفاء (`src/content/dedication.ts`) جزء ثابت من التطبيق وتنتقل كما هي إلى كل المنصات.

## لماذا لن نعيد البناء من الصفر

بُنيت الشيفرة بحيث يُعاد استخدام كل شيء تقريبًا عبر **Capacitor** (يغلّف تطبيق الويب نفسه في تطبيق أصلي):

| الطبقة | الويب الآن | الهاتف لاحقًا |
|---|---|---|
| الواجهة والصفحات (`src/features`) | React | **نفسها دون تغيير** |
| منطق العمل (`src/services`) | TypeScript | **نفسه** |
| المحتوى والبيانات (`public/data`, `src/content`) | ملفات مضمّنة | **نفسها** (تعمل دون إنترنت من أول تشغيل) |
| التخزين (`src/db`) | IndexedDB | IndexedDB داخل WebView (أو SQLite عبر إضافة عند الحاجة) |
| قدرات الجهاز (`src/platform`) | واجهات المتصفح | **تُستبدل هذه الطبقة فقط** بإضافات Capacitor |

## المرحلة الثانية: Android

1. إضافة Capacitor:
   ```bash
   npm i @capacitor/core @capacitor/cli @capacitor/android
   npx cap init "رفيق المسلم" org.rafiqalmuslim.app --web-dir dist
   npx cap add android
   npm run build && npx cap sync android
   ```
2. استبدال وظائف `src/platform/index.ts`:
   - **الإشعارات:** `@capacitor/local-notifications` — جدولة مواقيت الأيام القادمة (مثلًا 7 أيام) مسبقًا وإعادة الجدولة عند فتح التطبيق وعند تغيير المدينة أو الطريقة. مراعاة إذن `POST_NOTIFICATIONS` (Android 13+) و`SCHEDULE_EXACT_ALARM` وتحسينات البطارية لدى بعض الشركات المصنعة.
   - **الموقع:** `@capacitor/geolocation` مع إذن الموقع التقريبي فقط (يكفي للمواقيت).
   - **البوصلة:** إضافة مستشعر الاتجاه (أو واجهة `deviceorientation` داخل WebView مع اختبار على أجهزة متعددة).
   - **الصوت في الخلفية:** إضافة تشغيل أصلي مع Foreground Service وإشعار تحكم بالوسائط (مثل `@capgo/native-audio` أو إضافة مخصصة)، لأن WebView يوقف الصوت عند إغلاق الشاشة.
   - **المشاركة:** `@capacitor/share`.
3. الاختبار: أحجام شاشات مختلفة، الوضع الليلي، دون إنترنت، فصل/وصل الشبكة، إعادة تشغيل الجهاز (إعادة جدولة الإشعارات)، التوقيت الصيفي.
4. النشر: Google Play (رسوم تسجيل لمرة واحدة)، سياسة خصوصية (موجودة في `docs/PRIVACY.md`)، نموذج «أمان البيانات»: لا جمع بيانات.

## المرحلة الثالثة: iPhone (بعد استقرار Android)

1. `npm i @capacitor/ios && npx cap add ios` (يتطلب جهاز Mac وXcode).
2. **الإشعارات:** حد iOS للإشعارات المحلية المجدولة 64 إشعارًا ← جدولة 5 صلوات × ~10 أيام وإعادة الجدولة عند فتح التطبيق.
3. **الصوت في الخلفية:** تفعيل Background Modes → Audio، وإعداد AVAudioSession.
4. **البوصلة:** iOS يتطلب إذنًا صريحًا لمستشعر الاتجاه (منفّذ مسبقًا في `watchHeading`).
5. **الخصوصية:** نصوص أذونات `NSLocationWhenInUseUsageDescription` بالعربية، و«ملصق الخصوصية» في App Store: لا جمع بيانات.
6. **سياسات Apple:** التطبيق ليس مجرد غلاف لموقع (فيه محتوى ووظائف تعمل دون اتصال)، ولا مشتريات ولا روابط دفع.
7. النشر: Apple Developer Program (اشتراك سنوي؛ إعفاء محتمل للمنظمات غير الربحية).

## ما يجب الحفاظ عليه في كل الإصدارات

- رسالة الوفاء وصفحتها وبطاقة الرئيسية وسطر الإهداء — دون تغيير الاسم أو الكنية.
- المجانية الكاملة دون إعلانات أو اشتراكات أو طلبات تبرع.
- العمل دون حساب، والبيانات على الجهاز.
- اختبارات سلامة المصحف تعمل قبل كل إصدار.
