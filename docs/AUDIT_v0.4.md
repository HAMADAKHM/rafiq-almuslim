# رفيق المسلم 0.4 — التدقيق، والفجوات، وما نُفّذ

التاريخ: 20 أكتوبر 2026 • الفرع: `feature/v0.4-athkar-experience` (الفرع `main` لم يُمس، ونسخة 0.3.1 محفوظة فيه)

## 1. التدقيق: بنية المشروع الحالية

| البند | الحالة |
|---|---|
| التقنية | React 19 + TypeScript + Vite 8، وتطبيقا Android وiOS عبر Capacitor 8 |
| البيانات | IndexedDB محليًا (الإعدادات، العلامات، الملاحظات، الحفظ، السجلات، المفضلة)؛ لا خادم ولا حساب |
| المصحف | نص حفص العثماني من QuranEnc عبر `quran-json` مع تحقق آلي (114 سورة، 6236 آية، بصمة SHA-256، مقارنة مستقلة بـ `quran-meta`) |
| الصوت | EveryAyah مع مصدر بديل تلقائي Islamic Network، وتنزيل للاستماع دون اتصال |
| التفسير | ستة تفاسير من مستودع `tafsir_api` تُحمّل عند الطلب |
| الصلاة | مكتبة adhan مع 12 طريقة حساب وتعديل بالدقائق لكل صلاة، وتنبيهات مجدولة على Android/iOS |
| الاختبارات | 112 اختبار وحدة + 42 اختبارًا في المتصفح (Playwright) |

## 2. المقارنة بالتطبيق المرجعي «أذكار»

**تنبيه:** موقع athkarapp.com وصفحة Google Play **لم يكونا متاحين من بيئة العمل** (الشبكة محجوبة). لذلك لم أنسب إلى التطبيق المرجعي أي ميزة بعينها. المقارنة أدناه مبنية على قائمة المتطلبات في طلبك فقط. لم يُنسخ أي كود أو شعار أو أصل من أي تطبيق آخر: الرسوم والشعار في `src/components/Art.tsx` مرسومة بالشيفرة خصيصًا لرفيق المسلم.

| المتطلب | قبل 0.4 | بعد 0.4 |
|---|---|---|
| رئيسية هادئة ببطاقة الصلاة القادمة والعداد | بطاقة نصية بسيطة | بطاقة بمشهد مسجد يتغير لونه بحسب الصلاة، وعداد، والمواقيت الخمس، والتاريخان |
| شريط تنقل سفلي | قائمة جانبية منسدلة | شريط سفلي (الرئيسية، القرآن، المواقيت، الأذكار، المزيد) وصفحة «كل الأقسام» |
| اختصارات قابلة للتخصيص | ثابتة | يختار المستخدم حتى 8 اختصارات وتُحفظ |
| شاشة بداية وهوية مستقلة | لا | شاشة بداية بالشعار وسطر الصدقة الجارية، ولوحة ألوان موحدة، ووضعان فاتح وداكن |

## 3. ما لم يُنفَّذ ولماذا

| الميزة | السبب |
|---|---|
| أسماء الله الحسنى بمعانيها | لم يتوفر مصدر رقمي موثوق للمعاني يمكن التحقق منه من بيئة العمل، وكتابتها من الذاكرة تخالف شرط عدم اختلاق المحتوى |
| مجموعة الأحاديث والسيرة النبوية | السبب نفسه: تحتاج مصدرًا محققًا ومراجعة متخصص |
| تسجيلات صوتية للأذكار النبوية | لا يوجد تسجيل موثوق متاح للتحقق؛ الاستماع متاح فقط لعناصر الأذكار التي هي آيات |
| ودجات الشاشة الرئيسية | تحتاج شيفرة أصلية لكل نظام واختبارًا على أجهزة حقيقية |
| الأذان الكامل في الخلفية | التنبيهات مجدولة عبر النظام، لكن تشغيل صوت أذان كامل في الخلفية لم يُختبر على أجهزة حقيقية، وقيود iOS وتوفير الطاقة في Android قد تؤخره أو تمنعه |
| مقارنة مواقيت نابلس بتقويم الأوقاف الرسمي | التقويم الرسمي غير متاح من بيئة العمل. المواقيت محسوبة بطريقة «رابطة العالم الإسلامي»، ومتحقق منها بتنفيذ فلكي مستقل (فرق أقل من 2.6 دقيقة). يمكن تعديل الطريقة أو إضافة دقائق لكل صلاة من الإعدادات |

## 5. البيانات والتوافق

- كل الإعدادات الجديدة تُدمج مع إعدادات الإصدارات السابقة بقيم افتراضية (`mergeSettings`)، وعليها اختبار.
- لم تتغير قاعدة البيانات (`DB_VERSION` = 1)، ولم يُحذف أي سجل أو إعداد.
- الأذكار الشخصية ومتابعة الصلوات تُحفظ في مخزن `kv` المحلي.
- نص رسالة الوفاء واسم المرحوم وكنيته لم تتغير، ويحميها اختبار آلي.
- أُضيف سطر بصياغة صاحب المشروع: «صدقة جارية عن روح المرحوم الحاج قصي بديع خلفه «أبو محمد»». كُتب اسم العائلة «خلفه» بالهاء كما في النص الأصلي المعتمد، فإن كان الصواب «خلفة» فهو تعديل سطر واحد في `src/content/dedication.ts`.

## 6. الاختبار

ما نُفّذ فعليًا:

| الاختبار | النتيجة |
|---|---|
| `npm test` | 112 اختبار وحدة، كلها ناجحة |
| `npm run test:e2e` | 42 اختبارًا في Chromium، كلها ناجحة |

تشمل اختبارات المتصفح:
- جلسة الأذكار والانتقال التلقائي وتعطيله.
- استئناف الجلسة وتسجيل الإتمام التلقائي.
- الأذكار الشخصية (إضافة وتعديل وحذف).
- تخصيص الاختصارات وبقاؤه بعد إعادة التحميل.
- متابعة الصلوات وبقاؤها بعد إعادة التحميل.
- التنقل السفلي على شاشة 390 بكسل دون تمرير أفقي.
- خيار إبقاء الشاشة مضاءة.
- العمل دون اتصال.
- بقية اختبارات الإصدارات السابقة.

لقطات الوضعين الفاتح والداكن فُحصت بصريًا.

ما **لم** يُختبر:
- لم يُجرَّب التطبيق على هاتف حقيقي.
- لم يُختبر عمل الإشعارات والتلاوة والتطبيق مغلق.
- لم يُختبر Wake Lock داخل WebView على iOS.
- لم يُبنَ تطبيق iOS، لأن ذلك يحتاج جهاز Mac.

## 7. التشغيل والبناء

- **التطوير:** `npm install` ثم `npm run dev`.
- **الاختبار:** `npm test`، ثم `npm run test:e2e`.
- **Android:** يبني GitHub Actions ملف APK تلقائيًا عند كل دفع:
  - من فرع `main`: إصدار عادي برابط ثابت `releases/latest/download/RafiqAlMuslim.apk`.
  - من فروع `feature/`: نسخة معاينة (Pre-release).
  - محليًا: `npm run android:apk`، ويحتاج Android SDK.
- **iOS:** على جهاز Mac فيه Xcode: `npm run build && npx cap sync ios && npm run ios:open`، ثم التوقيع بحساب Apple Developer.
- **المفاتيح والخدمات:** لا يحتاج التطبيق أي مفتاح سري. النشر في المتاجر يحتاج مفتاح توقيع يُضاف أسرارًا في المستودع، ولا يُرفع ملفًا إلى المستودع.
